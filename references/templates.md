# Copy-ready Prompt Templates

## Requirement Understanding Pack

Use this before the final prompt when the user gives a raw idea or rough requirement:

```markdown
## 需求理解
- 真实目标：{用户真正想达成的结果}
- 逻辑链：{为什么做 → 关键约束 → 目标 agent 要完成什么 → 如何验收}
- 任务类型：{研究/写作/决策/代码/多模态/agent 工程/混合}
- 关键假设：{不问也可以继续的合理假设}
- 需要澄清：{只有危险或不可用时才提问}
- 误解风险：{目标 agent 最可能跑偏的地方}
```

## Universal Agent Prompt

```text
你是一名资深 {领域/角色}。请把下面需求当作一个需要高质量交付的任务，而不是简单聊天。

【我对需求的理解】
- 真实目标：{intent}
- 逻辑链：{why → constraints → deliverable → validation}
- 关键假设：{assumptions}

【我的目标】
{目标}

【背景与材料】
{背景、文件、链接、截图、数据、已有尝试}

【约束】
- {时间/预算/范围/风格/安全/格式约束}
- 不要做与目标无关的扩展或重构。
- 如果信息不足但可以合理假设，请先列出假设再继续；如果缺失会导致结果危险或不可用，请先问我。

【规格书约束】
- Scope：明确交付物、顺序、边界，以及哪些规则适用于全部内容。
- Length：明确输出格式和上限（章节/表格列/要点数/字数）。
- Positive target：用正向目标描述风格与行为；如有禁令，同时写出替代做法。
- Action verbs：按“提取/排序/比较/验证/生成/改写/汇报”等可执行动词推进。
- Tool trigger：说明是否需要搜索、读取文件、运行测试；需要时写明来源优先级和证据数量。
- Tone：说明目标读者、语气、直接程度或温暖程度。
- Go beyond basics / Polish：如果是创意/开放任务，像真实交付件一样打磨，并说明打磨标准。

【你的工作流】
1. 先判断任务类型：研究 / 写作 / 决策 / 代码 / 多模态 / agent 工程 / 混合。
2. 如果依赖最新事实，请搜索官方或一手来源，并标注日期和链接。
3. 先给出简短计划和成功标准。
4. 执行任务。
5. 主动反驳：指出薄弱假设、风险、反例和替代方案。
6. 对多步/agentic 任务，记录工具调用、关键假设、证据、文件或数据来源。
7. 给出验证方法、handoff 和下一步行动。

【输出格式】
- 结论摘要
- 详细结果
- 风险与不确定性
- 验证/验收方式
- 下一步建议
```

## Research Prompt

```text
请对 {主题} 做高质量研究。优先官方/一手来源，其次可信媒体/专家资料，最后才使用二手总结。

要求：
1. 判断哪些事实需要最新信息。
2. 使用来源表：URL、作者/机构、发布日期、访问日期、可信度、关键事实。
3. 区分确定事实、推断、观点和不确定点。
4. 对冲突来源做解释，不要强行合并。
5. 最后给出可执行建议。

输出：
- TL;DR
- 来源分层表
- 核心事实
- 分歧/不确定性
- 建议
```

## Decision / Strategy Prompt

```text
请作为严格但建设性的决策顾问分析 {决策/方案}。不要默认同意我。

背景：{背景}
目标：{要优化的结果}
约束：{时间/预算/资源/风险边界}

请执行：
1. 复述你对问题的理解，列出关键假设。
2. 给出 3 个可选方案，并用同一组标准比较。
3. 指出我最可能忽略的反例、失败模式和替代方案。
4. 推荐一个方案，并写出反对这个推荐的最强理由。
5. 把推荐方案缩小成可验证的下一步。

输出：结论 / 假设表 / 方案矩阵 / 风险 / 推荐 / 反对意见 / 验证计划。
Length：总计不超过 {字数/段落数}。
```

## Coding / Claude Code Prompt

```text
### ① 先逐条执行 Claude Code 高质量命令

每条命令单独发送，等返回后再发下一条；不要把多条 slash commands 一次性多行粘贴。

第 1 条：/clear {short-task-slug}
第 2 条：/model opus
第 3 条：/effort max
第 4 条：/status
第 5 条：/plan

如果确需远程深度计划，用：
/ultraplan <把下面完整任务 Prompt 粘在这里>

注意：/ultraplan 不是开关命令，不能单独输出一行 /ultraplan。

### ② 再粘贴任务 Prompt

ultrathink

你是资深软件工程师。请在 {项目路径/代码库} 中完成以下任务：{任务}。

开始前先确认：/model、/effort、/status，以及已进入 /plan 或 /ultraplan。不可用命令必须用 /help、claude --help 或 /status 核验，不要编造结果。

Success criteria：{可复跑命令或可观察行为}。

Output contract：请按 {章节/表格/清单} 输出，最多 {数量/字数/段落数}；每个结论都要说明证据或验证方式。

规则：
- 先快速阅读相关文件，列出关键假设和最小修改计划；计划确认前不要改文件。
- 只改与当前请求直接相关的文件；不要顺手重构、改格式、重排 import 或加未来扩展点。
- 优先最简单可维护实现。
- 若是 bugfix，先写/找能复现问题的测试或最小复现。
- 修改后运行：{测试/构建/类型检查命令}。
- 完成前如支持，执行 /diff、/simplify、/review、/security-review；重大/高风险任务加 /ultrareview。
- 提交最终报告：改了哪些文件、为什么改、Claude Code 质量命令执行记录、验证命令与结果、未解决风险。
- 涉及破坏性、外部可见、付费、生产或安全敏感操作前必须停下来问我。
```

## Agent Engineering Prompt

```text
你是 Agent Engineering 架构师。请把下面需求设计成可执行的 agent 工作流：{需求}。

请输出：
1. Agent Charter：使命、非目标、输入、输出、权限边界。
2. Context Plan：需要哪些文档、代码、数据、历史上下文；哪些信息不得假设。
3. Tool Plan：需要 browser / filesystem / GitHub / NotebookLM / tests / MCP / database 等哪些工具，什么时候用，如何确认工具结果。
4. Control Flow：plan → execute → observe → critique → verify → handoff。
5. Eval：成功标准、失败模式、回归测试或人工验收点。
6. Observability：记录关键假设、工具调用、来源、文件、命令和验证结果。
7. Guardrails：何时必须暂停请求确认。
8. Handoff：最终交付物、运行方式、验证结果、剩余风险、下一步。
9. 最小可行版本：先做什么，避免过度工程。
```

## Writing Prompt

```text
请作为资深编辑帮我完成 {写作任务}。

背景：{背景}
读者：{受众}
目标：{读者读完后要理解/相信/执行什么}
素材：{事实、要点、引用、链接}
语气：{风格}
风格目标：使用具体、可读、贴近读者的表达；用事实和例子支撑判断。
禁忌：不要空泛套话，不要 AI 味，不要编造事实；如需禁用某种写法，请同时给出替代表达。
长度/格式：{段落数/字数/标题层级/表格或清单要求}

流程：
1. 先提炼信息结构。
2. 给出提纲。
3. 写正文。
4. 自我批评：指出哪里可能空泛、证据不足或不符合读者。
5. 给出改进版。
```

## Multimodal / Data Prompt

```text
请分析我提供的 {图片/截图/PDF/表格/数据}。

观察目标：{要看什么}
不要泛泛评价；每个结论都要给证据。
如果后续我提供截图、报错、表格更新或运行结果，请基于新证据迭代，而不是重头泛泛分析。

输出：
- 你看到了什么（事实提取）
- 关键问题/模式
- 证据
- 建议
- 需要我补充的材料
```
